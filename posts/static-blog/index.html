我把博客做成了一个文件夹

没有数据库，没有后台，没有运行时。聊聊这个纯静态博客是怎么构建、怎么部署的。

这个博客的全部产物，是一个叫 dist 的文件夹。里面有 HTML、一份 CSS、一个很小的 JavaScript 文件，以及若干文本。把它丢到任何能托管静态文件的地方，它就能工作。

静态不是妥协#

动态博客需要服务器、数据库、运行时，还需要有人记得给它们打补丁。静态站点把这些都省掉了：请求进来，服务器返回一个早就写好的文件，结束。

这带来几个实际的好处：

  • 几乎不消耗资源，一台最小的机器能扛住很多访问；
  • 没有登录、注入、反序列化这类攻击面；
  • 备份就是复制文件夹；
  • 本地打开和线上打开，看到的是同一份东西。

代价也很清楚：评论、点赞、访问统计这些需要服务端的功能，要么接第三方，要么不要。我选择不要。

构建只有一条命令#

bash
node scripts/build.mjs

它按顺序做四件事：

  1. 读取 content/posts/ 下的 Markdown，解析 front matter；
  2. 渲染正文、生成目录，写出每一篇文章的 HTML；
  3. 生成首页、归档、标签页、RSS 和 sitemap；
  4. 复制静态资源，输出到 dist/。

整个过程不联网，也没有 node_modules。构建脚本自己实现了一个够用的 Markdown 渲染器，所以即使几年后 npm 生态变了，这条命令大概率还是能跑。

内容就是文本文件#

一篇文章长这样：

markdown
---
title: 文章的标题
date: 2026-10-21
summary: 列表里显示的一句话简介。
tags: [技术, 前端]
---

正文从这里开始。

没有后台编辑器，没有草稿箱接口。写文章就是新建一个 .md 文件，改完重新构建。听起来原始，但对一个更新频率不高的个人博客来说，这已经足够了。

部署：把 dist 放到任何地方#

方式费用说明
自己的服务器已有服务器nginx 指向 dist/，最自由，需要自己配 HTTPS
GitHub Pages免费推仓库，用 Actions 构建并发布
Netlify / Cloudflare Pages免费额度把 dist/ 拖进去即可，适合不想碰命令行的人

因为产物完全是静态的，换托管方不需要改任何代码，最多改一下域名解析。

小技巧

如果只是想先看看效果，python -m http.server 4173 --directory dist 就够了，不需要安装任何东西。

一点代价#

静态站点没有「实时」。文章发布需要重新构建，评论需要外部服务，搜索只能靠一份预先生成的 JSON 索引——这个博客的搜索就是这样做的，输入关键词，在浏览器里过滤几十篇文章，快得几乎无感。

对个人博客来说，这些限制换来的是简单。而简单，通常意味着能活得更久。
